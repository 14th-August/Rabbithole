## 1. Overview

- **What it is:** a student marketplace app for Vancouver Island University students to trade and re-sell textbooks and misc. items.
- **Client:** Expo / React Native app, Expo SDK **57**, file-based routing via `expo-router`.
- **Repo:** `github.com/14th-August/Rabbithole` — branch `main`.
- **Repo root** is `Rabbithole/`; the Expo app lives in the nested `rabbithole/` subfolder.
- **Status:** navigation shell scaffolded, screens are empty stubs. No backend, no state layer, no data models in code yet.
- **Mental model:** `src/app/` is the router. Every file in it is a URL. Nothing else in the project is a route.
- **Next up:** infra & system design — agenda in [[#6. Open Questions]].

## 3. Routing Map

### The rule
- `src/app/` **is** the route table. File path = URL path. There is no route config file.
- Adding a file to `src/app/` creates a route. Deleting it removes one.

### Conventions (expo-router, SDK 57)
- `_layout.tsx` — wraps every route in its directory; defines *how* those pages are arranged. Not itself a route.
- `index.tsx` — the default route for its directory (`products/index.tsx` → `/products`)
- `(folder)/` — **route group**. Organises files without adding a URL segment. `(tabs)/items.tsx` → `/items`, **not** `/tabs/items`.
- `[id].tsx` — dynamic route. `products/[productId].tsx` matches `/products/123`.
- `+not-found.tsx` — catch-all fallback (not yet present in this project)

### Layout components
- `<Stack />` — push/pop navigation with an automatic back button
- `<Tabs />` — bottom tab bar; children configured via `<Tabs.Screen name="..." options={{ title: '...' }} />`
- `<Slot />` — renders children with no navigator; use when you want a plain header/footer wrapper

### Current route table
- `/` → `src/app/index.tsx` — placeholder screen
- `/` (tab group home) → `src/app/(tabs)/index.tsx` — empty
- `/items` → `src/app/(tabs)/items.tsx` — empty
- `/messages` → `src/app/(tabs)/messages.tsx` — empty
- `/profile` → `src/app/(tabs)/profile.tsx` — empty
- `/wishlist` → `src/app/(tabs)/wishlist.tsx` — empty

### ⚠️ Known collision
- Both `src/app/index.tsx` and `src/app/(tabs)/index.tsx` resolve to `/`. Route groups don't add a segment, so these two compete for the same path. One of them has to go — most likely the bare `src/app/index.tsx` placeholder.

### Typed routes
- `app.json` sets `experiments.typedRoutes: true`, so route strings are type-checked against the file tree.
- Types are generated into `.expo/types/` (gitignored, included by `tsconfig.json`). They regenerate on `expo start` — a stale or missing `.expo/` means route types won't resolve.

### Likely routes to add later
- `/items/[id]` — item detail
- `/messages/[threadId]` — conversation thread
- `(auth)/` group — sign-in / sign-up, outside the tab bar
- `/listings/new` — create-a-listing flow

- `expo-font` `~57.0.3` — custom font loading
- `react-native-reanimated` `4.5.1` + `react-native-worklets` `0.10.1` — UI-thread animation
- `react-native-gesture-handler` `~2.32.0` — native gesture system
- `react-native-web` `~0.21.0` — web target

### Platform services
- `expo-constants` `~57.0.17` — app manifest / build constants at runtime
- `expo-device` `~57.0.1` — device info
- `expo-linking` `~57.0.9` — deep links, paired with the `rabbithole://` scheme
- `expo-splash-screen` `~57.0.8` — splash control
- `expo-status-bar` `~57.0.1` / `expo-system-ui` `~57.0.3` — system chrome
- `expo-web-browser` `~57.0.2` — in-app browser; the usual OAuth redirect path

### Notable absences (decisions still open)
- No state manager (Zustand / Redux / Jotai)
- No data-fetching layer (TanStack Query / SWR)
- No backend SDK (Supabase / Firebase / custom client)
- No auth library
- No form or validation library (react-hook-form / zod)
- No test runner (Jest / Vitest / Maestro)
- `expo lint` is scripted but no ESLint config file exists yet
- See [[#6. Open Questions]]

### Version discipline
- Expo pins deps to SDK-compatible ranges. Bump with `npx expo install --check`, not `npm update` — hand-bumping native modules past the SDK's supported range breaks the build.

## 5. App Config

### `app.json` — Expo config
- `name` / `slug`: `rabbithole`, `version`: `1.0.0`
- `scheme`: `rabbithole` — deep link base, `rabbithole://`. Also what OAuth redirects come back to.
- `orientation`: `portrait` (locked)
- `userInterfaceStyle`: `automatic` — follows system light/dark. **Any UI built must handle both themes.**

#### iOS
- `ios.icon`: `./assets/expo.icon` — Apple Icon Composer bundle (layered icon, iOS 18+ tinted/dark variants)
- No `bundleIdentifier` set yet — **required before any real iOS build**

#### Android
- `package`: `com.keishyi.rabbithole`
- `adaptiveIcon`: background `#E6F4FE` + foreground / background / monochrome PNG layers
- `predictiveBackGestureEnabled`: `false`

#### Web
- `output`: `static` — exports a static site
- `favicon`: `./assets/images/favicon.png`

#### Plugins
- `expo-router`
- `expo-splash-screen` — bg `#208AEF`, `splash-icon.png` at width 76

#### Experiments
- `typedRoutes: true` — route strings type-checked against the file tree
- `reactCompiler: true` — React Compiler auto-memoisation. Means **don't hand-write `useMemo` / `useCallback`** as a reflex; the compiler handles it. Code must follow the Rules of React or the compiler bails silently.

### `tsconfig.json`
- Extends `expo/tsconfig.base`, `strict: true`
- Path aliases:
  - `@/*` → `./src/*`
  - `@/assets/*` → `./assets/*`
- `include` covers `**/*.ts`, `**/*.tsx`, `.expo/types/**/*.ts`, `expo-env.d.ts`
- Import as `@/app/...` or `@/assets/images/...` — never long relative chains

### Brand colours in play
- `#208AEF` — splash background (primary blue)
- `#E6F4FE` — Android adaptive icon background (pale blue)
- No shared theme/token file exists yet; these live only in `app.json`. Worth extracting.

### npm scripts
- `npm start` → `expo start`
- `npm run android` → `expo run:android` (native build, needs prebuild)
- `npm run ios` → `expo run:ios` (native build, macOS only)
- `npm run web` → `expo start --web`
- `npm run lint` → `expo lint`
- `npm run reset-project` → ⚠️ **broken**, points at `./scripts/reset-project.js` which doesn't exist

## 6. Open Questions

### Bugs / blockers in the current tree
- `src/app/(tabs)/_layout.tsx` renders `<Stack />` and is byte-identical to the root layout. A tab group needs `<Tabs />` from `expo-router`, with a `<Tabs.Screen>` per route.
- All six tab route files are 0 bytes. expo-router requires a default-exported component per route — these will throw on mount.
- Route collision: `src/app/index.tsx` and `src/app/(tabs)/index.tsx` both resolve to `/`. See [[#3. Routing Map]].
- `package.json` scripts `reset-project` → `./scripts/reset-project.js`, which doesn't exist.
- `rabbithole/README.md` is untouched create-expo-app boilerplate.
- No `ios.bundleIdentifier` in `app.json`.
- `.idea/` and `.vscode/` are committed to git — usually you'd want `.idea/` ignored.

### Asset gaps
- `assets/images/tabIcons/` has `home` and `explore` only — 2 sets for 5 tabs.
- `explore` icon has no matching route. Is `explore` the intended name for `items`? Naming needs reconciling before the tab bar is wired.
- Expo template art (`react-logo*`, `expo-badge*`, `expo-logo`, `tutorial-web`, `logo-glow`) is dead weight and can be deleted.

### Decisions not yet made — the infra/system-design agenda
- **Backend**: the root README shows an ER diagram, so a relational schema exists on paper — but nothing in code. Supabase / Firebase / custom API?
- **Auth**: VIU student verification is the whole premise. Email-domain check? SSO? Manual review?
- **State + data fetching**: no library chosen.
- **Images**: listings imply user uploads — storage, resizing, CDN all unaddressed.
- **Messaging**: real-time (websockets/realtime subscriptions) vs polling.
- **Payments**: is money handled in-app, or is it arrange-in-person only? Big scope fork.
- **Web target**: `web.output: "static"` is set — is web an actual target or just leftover default?

### Structural gaps to fill as the app grows
- `src/components/` — shared UI
- `src/lib/` or `src/api/` — data client
- `src/hooks/`
- `src/types/` — mirror the ER diagram as TS types
- `src/theme/` — extract `#208AEF` / `#E6F4FE` and handle light + dark (`userInterfaceStyle: automatic`)
- `(auth)/` route group outside the tab bar
- ESLint config file
- Tests
